# 旅帖（たびちょう）

**旅の思い出を積み重ね、日々の暮らしに彩りを添える旅行記録アプリ**

## 1. サービス概要

旅帖（たびちょう）は、旅先で撮った写真と、そのときの気持ちや出来事を一緒に残せる旅行記録アプリです。

写真だけでは忘れてしまいがちな旅の記憶を、自分らしい言葉で綴り、いつでも振り返ることができます。

誰かに見せるためではなく、自分自身のために思い出を残し、日々の暮らしの中でも旅の楽しさや懐かしさを感じられる場所を目指しています。

## 2. このアイデアはどこから生まれたか

### 2-1. きっかけとなった体験・感情

旅行先では、きれいな景色や印象に残った場所など、さまざまな場面で写真を撮ります。しかし、時間が経ってから写真を見返すと、いつ、どこで撮った写真なのか、なぜその場所で写真を撮ろうと思ったのかを思い出せないことがありました。

写真を見れば、そのときに見ていた景色は思い出せても、どんなことをしていたのか、何を感じていたのかまでは、なかなか思い出せません。

せっかく楽しかった旅行なのに、写真だけでは残しきれない記憶があることに、もったいなさを感じました。

### 2-2. なぜそれが「気になった」のか

私はもともと、写真を撮ることや、旅先の景色、街並みを眺めることが好きです。

また、旅先で過ごした時間や、その場所で感じたことも、自分にとって大切な思い出の一部だと考えています。

写真は、その瞬間を形に残してくれるものです。しかし、写真を撮ったときの気持ちや、その場で起きた出来事まで、すべて残せるわけではありません。

だからこそ、写真を見返したときに、景色だけでなく、そのときの気持ちや出来事まで思い出せるようにしたいと思いました。

思い出を誰かに共有するためだけではなく、自分自身がいつでも振り返れる形で残しておきたい。そんな思いから、旅の記録を残すためのサービスを考え始めました。

## 3. 課題の整理

### 3-1. 表に見えている困りごと

旅行中に撮った写真はスマートフォンなどに保存しているものの、旅行後に整理したり、そのときの出来事や気持ちを書き残したりする機会はあまりありません。

そのため、時間が経ってから写真を見返しても、撮影した場所や当時の出来事、感じていたことを十分に思い出せないことがあります。

また、旅行の記録を残そうと思っても、写真を選んだり、文章を書いたりする作業を負担に感じ、記録を残さないままになってしまうこともあります。

### 3-2. 本当に解決したい課題は何か

**なぜ、写真を見返しても当時の思い出を十分に振り返れないのでしょうか。**

1. 写真には景色が残っていても、そのときの気持ちや出来事までは残っていないことがあるからです。
2. なぜ気持ちや出来事が残らないのでしょうか。旅行中はその瞬間を楽しむことが中心になり、記録を残すことまでは意識しにくいからです。
3. なぜ記録を残すことが難しいのでしょうか。旅行後に写真を整理し、出来事や気持ちを文章にまとめるには、時間や手間がかかるからです。

これらのことから、解決したい課題は、単に旅行の記録を保存する場所がないことではなく、**旅の思い出を残したいと思っていても、記録する手間によって、そのときの気持ちや出来事を残しきれず、時間が経つにつれて思い出が薄れてしまうこと**だと考えています。

旅の記憶をすべて詳細に記録する必要はありません。写真と一緒に短い言葉を残すだけでも、あとから思い出を振り返るきっかけになります。

記録する負担を減らし、思い出を無理なく残せるようにすることで、旅の記憶をより長く大切にできるサービスを目指します。

## 4. 想定ユーザーについて

### 4-1. 想定しているユーザー

**年齢設定**

- **年齢：** 20代〜30代を中心に想定しています。
- **理由：** スマートフォンで写真を撮り、デジタル上で管理することに慣れている人を想定しています。年齢だけでなく、旅の思い出を大切に残したいという気持ちを重視します。

**生活・状況設定**

- **生活・状況：** 旅行先で写真を撮ることが好きで、旅行後に写真を整理したり、旅行記を書いたりする時間をなかなか取れない人です。
- **理由：** 写真は残していても、当時の気持ちや出来事までは記録できていないという課題を、写真と短いメモを一緒に残せる仕組みで解決します。

**環境設定**

- **環境：** 旅行の写真をスマートフォンなどに保存しており、SNSで発信するよりも、自分のために思い出を残したい人です。
- **理由：** 他人に見せることを前提としない設計にすることで、周囲の反応を気にせず、自分の言葉で自由に記録できる場所を提供します。

### 4-2. 自分とユーザーの距離

**自分自身**

旅行の写真を見返しても、当時の出来事や気持ちを思い出せないことがあるという、自分自身の経験がアイデアの出発点です。

自分の経験を活かしながら、実際に使ってもらった人の意見も取り入れ、使いやすいサービスへ改善していきたいと考えています。

### 4-3. 実際に使われる可能性について（需要・存在確認）

- **最初に使ってくれそうな人：** 旅行が好きで写真をよく撮る人や、旅行の思い出を日記などに残すことが好きな人。
- **使うきっかけ：** 旅行後に写真を見返したときや、過去の旅行を懐かしく思い出したとき。
- **今使っている代替手段：** 写真アプリ、メモアプリ、日記、SNS
- **旅帖を使う理由：** 写真と気持ちや出来事を一緒に残し、他人に見せることを前提とせず、自分のために思い出を振り返れることができるため。

### 4-4. ユーザーがサービスを導入して利用するまでのイメージ（導入・継続の流れ）

旅行計画時の情報収集などでSNSを利用した際に広告などでこのアプリのコンセプトを知り、次の旅行の際に使ってみようと導入します。

入力項目を必要最低限にすることで、旅行記を詳しく書くことが苦手な人でも気軽に利用できることや、旅行のたびに記録を積み重ねることで、過去の旅を振り返る楽しみが生まれ、日常の中でも当時の景色や気持ちを思い出せることが、継続利用につながると考えています。

## 7. このアプリで実現すること

### MVPで作る機能

まずは、旅の写真とそのときの気持ちや出来事を記録し、あとから振り返るという体験を実現するために、必要な機能に絞って開発します。

- **ユーザー登録・ログイン**
    - 名前、メールアドレス、パスワードによるユーザー登録
    - メールアドレスとパスワードによるログイン
- **旅行の記録**
    - 写真の登録
    - 日付・場所の登録
    - そのときの気持ちや出来事を記録するメモ
    - 記録の編集・削除
- **記録の閲覧**
    - 自分の記録を一覧で表示
    - 個々の記録の詳細を表示
- **プライバシーへの配慮**
    - 自分の記録を自分だけが閲覧できる設計
    - 他人への公開・共有機能は設けない

### 本リリースで作る機能

MVPで基本的な記録・閲覧機能を完成させたうえで、利用のしやすさや、思い出を振り返る楽しさを広げる機能を追加していきます。

- 1つの記録に複数の写真を登録する機能
- 地図上で旅先を振り返る機能
- 時系列で旅行の記録を閲覧する機能
- 行きたい場所を保存する機能
- 旅行の計画を管理する機能
- 記録を検索・分類する機能

## 8. このアプリの懸念点とその対策

### 懸念点①：記録することが負担になり、継続して利用されなくなる

- **何が問題になりそうか：**

    旅行のたびに写真を選び、日付や場所、気持ちなどを入力することが面倒になり、記録が続かなくなる可能性があります。

- **なぜそう思うか：**

    旅行中はその場を楽しむことが中心になり、帰宅後も写真の整理や旅行の振り返りに時間をかけられないことがあるため。また、時間が経つほど当時の気持ちや出来事を思い出しにくくなり、記録するための文章を考えること自体が負担になる可能性もあります。

- **そのために考えている対策：**

    記録するタイミングは、旅行中のさまざまな場面を想定しています。例えば、ホテルで同行者とその日の出来事を振り返ったあとや、寝る前にSNSへ投稿する写真を選びながら見返しているとき、次の目的地へ向かっている移動中などです。旅の途中で写真を見返したり、その日の出来事を思い出したりしたときに、気軽に記録を残せることを目指します。

    そのため、入力項目を必要最低限にし、写真と短いメモだけでも記録できることで、短い時間でも、旅行中に感じたことや印象に残った出来事を、忘れないうちに残せるようにします。すべてを詳しく書く必要はなく、写真と一言だけでも記録できるようにすることで、記録すること自体が旅行の負担にならないようにします。こうした旅の合間に無理なく記録できることが、継続して利用するきっかけになると考えています。

### 懸念点②：個人的な記録や写真が第三者に見られてしまう

- **何が問題になりそうか：**

    旅帖には、旅行の写真だけでなく、個人的な気持ちや出来事も記録されます。そのため、意図しない相手に閲覧されることは、ユーザーの安心感を損なう大きな問題になります。

- **なぜそう思うか：**

    旅帖は、自分のためだけに思い出を残せる場所を目指しています。安心して自由に記録できることが、サービスのコンセプトを実現するうえで重要だからです。

- **そのために考えている対策：**

    ユーザーごとに記録へのアクセス権限を確認し、他のユーザーが記録を閲覧・編集・削除できないようにします。また、画像の保存先についても、認証されていない第三者が直接アクセスできない仕組みを検討します。

## 9. 今後の展開・発展の方向性

### 機能追加の方向性

- **複数の写真を登録する機能：** 1つの旅の中で撮った複数の写真をまとめ、当時の出来事をより豊かに振り返れるようにします。
- **地図上で旅先を振り返る機能：** 訪れた場所を地図上に表示し、どこへ旅をしたのかを視覚的に振り返れるようにします。
- **タイムライン機能：** 旅行の記録を時系列で並べ、過去の旅の積み重ねを感じられるようにします。
- **行きたい場所・旅行計画の管理：** これから訪れたい場所や旅行の計画を記録し、過去の思い出だけでなく、これからの旅にもつなげられるようにします。
- **検索・分類機能：** 日付や場所などから過去の記録を探しやすくし、見返したい思い出にたどり着きやすくします。

### UI・体験の改善

記録を残すことが負担にならないよう、入力項目や操作手順を見直し、気軽に記録できる使い心地を目指します。

また、記録が増えても見たい思い出を見つけやすく、写真や文章を眺めながらゆっくり振り返れる画面づくりを大切にします。

### デザインコンセプト

植物標本や古い植物図鑑、旅の日記を思わせる、自然でどこか懐かしいデザインを目指しています。

- **カラー：** セージグリーン、オリーブ、生成りなど、自然を感じる落ち着いた色合い
- **モチーフ：** 葉や植物標本、旅の足跡、ノート
- **雰囲気：** 温かみがあり、穏やかで、長く使いたくなるデザイン
- **UI/UXの方針：** 思い出を気軽に記録でき、後から心地よく振り返れることを重視します。

### 機能以外の工夫

旅帖は、旅の記録を他人に見せるためではなく、自分自身が大切に振り返るためのサービスです。

そのため、他人との交流や投稿への反応を中心とするのではなく、自分のペースで記録を積み重ねられることを大切にします。

将来的には、旅の記録が一冊の旅行記のように積み重なり、ページをめくるように過去の旅を振り返れる体験を目指します。旅帖を開くことで、当時の景色や気持ちを思い出し、「また旅に出たい」と感じられるような場所にしていきたいと考えています。

## 10. 技術スタック（手段としての技術）

### 10-1. 使用予定の技術

| 項目              | 使用予定の技術     |
| ----------------- | ------------------ |
| フレームワーク    | Rails(ERB)         |
| CSSフレームワーク | Tailwind CSS       |
| データベース      | PostgreSQL（Neon） |
| 画像の保存先      | Cloudinary         |
| デプロイ先        | Render             |
| 開発環境          | Docker             |

### 10-2. 技術選定の比較検討

**Ruby / Ruby on Rails**
Wカリキュラムで学習した技術を活用し、これまでに学んだ知識を実際のWebアプリケーション開発に応用するため。

**Tailwind CSS**
デザインを柔軟に調整するため。Bootstrapも候補として検討しましたが、Tailwind CSSのほうがより柔軟な調整ができ、独自のデザインを細かく表現しやすいことから採用しました。

**PostgreSQL（Neon）**
Railsとの親和性が高く、ユーザー情報や旅行記録など、関連するデータを管理するのに適しているため。また、クラウド上でPostgreSQLを利用できるNeonを使用することで、データベース用のサーバーを自分で構築・管理する負担を抑えることができるため。

**Cloudinary**
Railsとの連携方法が用意されているため、画像を扱う機能を実装しやすいため。再デプロイ時などにローカルのディスクに保存した画像消えることを避けるため、外部のストレージとしてCloudinaryを採用しました。

**Render**
デプロイや運用の設定を進めやすく、アプリケーションの開発に集中しやすい点を重視したため。

**Docker**
開発環境を構築・統一し、必要なソフトウェアや設定を管理しやすくするため。

### 10-3. キャッチアップ不足の懸念

画像保存や外部サービスとの連携、ユーザーごとのアクセス制御などは、調査や検証に時間がかかる可能性があります。

そのため、まずはユーザー登録や旅行記録の登録・閲覧といった基本機能を実装し、段階的に知識を補いながら開発を進めます。

ReactやNext.jsなどの技術にも関心はありますが、MVPではRailsを中心とした構成を優先します。基本機能を完成させたうえで、必要性に応じて新しい技術の導入を検討します。
